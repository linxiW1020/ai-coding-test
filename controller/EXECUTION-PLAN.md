# 已授权的真实试点执行方案

这份方案只适用于 `https://github.com/linxiW1020/ai-coding-test`，不涉及其他仓库、部署、花费API费用或机器全局设置。用户于2026-10-22明确回复“授权”，允许按本方案执行提交、推送、PR、仓库规则及满足政策后的试点合并；无需重复确认同一范围。

## 授权动作与顺序

1. 将已审查的本地初版提交并首次推送到 `main`：控制器、单元测试、CI、说明及明确标注的CI状态判定试点模块。样例聚合函数保留构造缺陷用于真实修复任务，基础检查与控制器检查须通过。
2. 在本地 Chrome 中配置并核验 `main`：要求 PR、必需 `verify`成功和适用的更新检查，禁止force push及绕过。控制器在条件满足时执行正常 squash merge，不依赖仓库的延迟 auto-merge 开关。若平台实际不支持某项，记录限制并停止依赖步骤，不降低标准凑通过。
3. 仅给已确认的本试点任务启用提交、推送、创建PR权限。`merge_policy`启用须有用户对下列条件的明确确认。
4. 从 `codex/pilot-ci-status-001` 运行真实修复：Codex生成提案、控制器校验及应用、外部验收、新会话审查、推送、Chrome创建或复用PR、实际CI反馈、门禁及合并后检查。
5. 在 `codex/fault-*`隔离分支/PR验证必要负例：失败CI确实阻止合并、新提交不能沿用旧结果、重复触发不重复创建、未知动作先对账。故意失败只用于这些试验分支，不直接写main，不使用管理员强制合并。

外部许可通过`grants.task_ids`限定任务身份；首个真实任务为`pilot-ci-status-001`。隔离负例按已授权演练逐项登记ID，执行时关闭其合并许可。每个任务采用3次实现、10次模型调用、20分钟的独立预算批次；当前已停止的试点如需新批次，显式续预算并保留历史。

## 自动合并的具体条件

- 本仓库目标 `main`，本轮只运行已确认的试点任务。
- 仅 `src/**`与 `tests/test_ci_status.py`，最多5个变化文件。
- 代码、CI配置、控制器和其他受保护文件的范围由确定性检查核对；保护文件变更不允许自动合并。
- 当前完整head/base SHA匹配；本地 `verify`与独立 `acceptance`执行成功；独立只读审查无阻断项。
- GitHub必需 `verify`真实成功，所需平台审查满足、非Draft、无冲突、规则已核验、无绕过；证据不超过15分钟。
- 未执行、跳过、中性、等待和未知均拒绝；代码或基线变更后旧证据失效。
- 合并后读取真实merge SHA，再在当前主分支的干净独立工作树检查。该结果不等于用户产品验收。

## 当前先决条件

独立 Codex → 本地 Chrome 的能力预检必须真实通过，并核对实际 GitHub 页面状态能被当前只读适配器准确识别。浏览器不通或页面不能确定识别时保存证据并停止网页动作，不使用其他浏览器、Cookie、API或关闭沙箱来绕过。读取本地文件和控制器自检仍可继续。

## 可恢复性

所有自动编码发生在独立工作树。分支、PR、状态与日志作为可恢复证据保留；不清除用户材料、不重写历史。若合并后检查失败，停止后续任务并形成可审查修复或revert方案，实际回退另按授权处理。
